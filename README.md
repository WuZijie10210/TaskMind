# TaskMind｜AI 对话成果复用

**先推进任务，自然接住成果。**

用户用 AI 做方案、报告或研究整理时，会在多轮对话里形成判断、框架和方法。这些中间产出常混在聊天记录里；任务结束后，用户未必会专门整理，下次需要时也难以定位和复用。TaskMind 探索的是：**怎样让有用的阶段产出在任务推进中留下来，又不要求用户额外维护一套知识库？**

[在线体验](https://taskmind-production-050c.up.railway.app/) · [产品设计简介](https://taskmind-production-050c.up.railway.app/about) · [早期调研分析](https://docs.qq.com/slide/DWnBuUUdwUmhDS01Y)

## 解决方案

**以任务组织对话 → 主线推进、支线探索 → 用户发起整理 → AI 提炼候选、用户确认成果 → 在后续对话中引用。**

1. **让探索自然分流。**主线持续推进任务；遇到值得单独追问的问题，可以从当前节点展开支线。支线保留展开时的背景，之后独立探索，不会自动改写主线。
2. **在需要复用时留下成果。**用户主动触发阶段整理，AI 从当前对话提出候选。用户判断是否值得保留并确认后，它才成为可调用的成果。成果可以是内容，也可以是框架、判断或方法。
3. **按记忆方式找回成果。**知道具体内容时用 `@成果`；只记得内容来自哪个任务时用 `@任务`，系统仅从该任务**已确认的成果**中匹配相关内容。

**不是保存聊了什么，而是保存聊出了什么。**主线、支线与不同任务之间不自动共享对话过程；只有用户明确调用的已确认成果会进入新的对话。发送消息时保存实际引用内容的快照，便于回看当时依据的版本。

## 关键设计判断

手工归档要求用户在任务之外命名、分类、维护资料；完全自动保存又容易把尚未认可的内容带进下一次对话。TaskMind 把整理放在任务推进中的需要处：用户决定留下什么，AI 帮忙提炼；调用时可从任务出发寻找，不必记住成果的准确名称。它尝试在用户控制与复用成本之间找到一个可行的平衡。

早期[调研分析](https://docs.qq.com/slide/DWnBuUUdwUmhDS01Y)以学习任务为切入场景，帮助识别资料可信度、整理成本和个人判断保留等问题；产品机制面向方案、报告等需要多轮推进的任务，不以学生场景为边界。现有在线示例采用学习任务，供访客体验主线、支线、成果确认与跨任务调用。

## 当前实现与下一步

公开体验版已支持任务中的主线与支线、主动整理与确认成果、`@成果` 和 `@任务` 引用。访客数据按浏览器隔离，定期清理，并设有每日使用额度。

下一步将针对候选成果是否贴合用户当下的保留意图，优化整理触发时机、成果粒度和确认界面，并重点验证**候选成果的保留率**与**后续任务中的调用率**。这些指标是后续验证目标，现有版本尚未积累可代表真实使用效果的数据。

## 技术与本地运行

React 前端与 Express API 由一个 Node 服务提供；PostgreSQL 保存任务、消息、支线起点快照、整理记录、已确认成果及引用快照。模型调用在服务端通过兼容 OpenAI Chat Completions 的接口完成，密钥不进入浏览器。

需要 Node.js 20+ 和 PostgreSQL。复制 `.env.example` 为 `.env`，设置以下变量：

| 变量 | 用途 |
| --- | --- |
| `DATABASE_URL` | PostgreSQL 连接地址 |
| `AI_API_KEY` | AI 服务提供方的密钥 |
| `AI_BASE_URL` | 与密钥对应的 Chat Completions API 基础地址，通常以 `/v1` 结尾 |
| `AI_MODEL` | 提供方支持的模型，须支持流式输出及 `max_tokens` |
| `SESSION_SECRET` | 生产环境至少 32 个随机字符，部署后保持稳定 |
| `PUBLIC_ORIGIN` | 可选；公开站点的来源地址 |

密钥、地址和模型应属于同一服务提供方。不要将 `.env` 或密钥提交到公开仓库。

```sh
npm ci
node --env-file=.env app/migrate.cjs
npm run build
node --env-file=.env app/server.js
```

默认访问 `http://localhost:3000`。Docker 部署时会应用新增数据库迁移；健康检查路径为 `/healthz`。运行 `npm test` 检查对话上下文、引用边界、访客隔离和示例；运行 `npm run build` 检查前端构建。
