# TaskMind｜AI 对话成果复用

**先推进任务，自然接住成果。**

用 AI 做方案、报告等复杂任务时，有价值的提纲、判断、框架和方法常产生在中途，却与临时探索和被放弃的方向混在长对话里。任务结束后，用户通常不会专门整理；之后想用时，又难找到、难判断它能否接上当前任务。

[在线体验](https://taskmind-production-050c.up.railway.app/) · [产品设计介绍](https://taskmind-production-050c.up.railway.app/about) · [早期调研分析](https://docs.qq.com/slide/DWnBuUUdwUmhDS01Y)

## 问题与机会

早期的用户访谈、问卷和竞品分析从学习任务切入，帮助我识别长对话中的三个断点：过程难接续、内容不敢直接留下、成果难复用。进一步看，用户是否愿意沉淀和复用，还取决于两道成本。

**沉淀有成本。** 用户正关注当前任务如何继续。此时要求他额外整理、命名和归档，是一项马上要做的工作，而内容的未来价值尚不确定；阶段成果也容易与试错过程混在一起。

**调用有成本。** 用户可能只记得“上次在某个任务里讨论过”，却想不起成果名称、在哪轮对话里、当时为什么这么判断。如果要翻记录、重建语境，再决定能否用于眼前任务，重新问 AI 可能显得更省事。

**信任贯穿两步。** 用户需要能回看成果来自哪段任务对话，自己决定候选是否值得保存，并知道历史内容进入新对话的边界。确认成果表达的是“这值得我留下”，不意味着其中的事实已自动核实。候选是否贴合当下需求、调用后能否适用于新任务，也都需要用户判断。

[早期调研分析](https://docs.qq.com/slide/DWnBuUUdwUmhDS01Y)以学习任务为切入场景；TaskMind 探索的是方案、报告等持续任务中同样可能出现的成果复用问题。上述关于整理与调用行为的解释是产品设计判断，仍需通过实际使用验证。

## 核心方案

**任务 → 主线与支线 → 主动整理 → 确认成果 → 后续调用**

**1. 承接任务过程。** 主线推进核心目标；支线从某个主线节点展开，承接阶段探索或方向验证。支线继承展开时的背景，之后独立推进，也可以被放下。分流让有用内容有更清晰的产生位置。

**2. 轻量确认成果。** 当用户觉得一段探索值得留下，或需要把支线所得带回主线时，主动发起整理。AI 根据当前对话提炼候选；用户可回看来源、改名、调整或移除候选。只有确认后的内容才成为可引用成果。AI 降低提炼成本，用户保留判断权。

**3. 便捷调用成果。** 后续对话提供两种入口，让用户按自己记得的线索找回成果：

| 引用方式 | 用户此时记得什么 | 系统使用什么 |
| --- | --- | --- |
| `@成果` | 知道具体要用哪份成果 | 用户指定的已确认成果 |
| `@任务` | 记得内容来自哪个任务，但不记得成果名称 | 仅从该任务已确认成果中匹配相关内容 |

对话之间不自动共享过程。支线的聊天不会直接进入主线，历史任务的原始对话也不会因为 `@任务` 被读取；只有用户明确调用的已确认成果进入新对话。已发送消息保留当时实际引用内容的快照，便于回看。

## 关键设计判断

TaskMind 试着让整理发生在用户已经意识到阶段产出有用、或正需要跨对话调用的时候，而不是要求用户随时为不确定的未来做归档。整理仍由用户主动触发；“自然接住”指降低提炼与确认的负担，并非自动沉淀。

复用从用户记得的任务出发：知道具体内容时用 `@成果`，只记得来源时用 `@任务`。系统帮助找回候选的已确认成果，用户仍可判断它是否适合当前任务。信任不是一次性的附加步骤，而是贯穿成果的产生、确认和再次使用。

**不是保存聊了什么，而是保存聊出了什么。** 用户不用刻意维护知识库，也有机会让任务中的阶段成果继续发挥作用。

## 当前版本与下一步

[在线 Demo](https://taskmind-production-050c.up.railway.app/)已支持主线与支线、主动整理与确认成果、`@成果` 和 `@任务` 引用。预置任务用于体验这些交互；访客数据按浏览器隔离并定期清理。

下一步重点优化整理的触发时机、候选成果的粒度与确认展示，并验证用户是否愿意确认候选、是否能在后续任务中找到并调用它们。成果保留率和后续调用率是计划观察的指标，当前尚无能代表真实使用效果的数据。
