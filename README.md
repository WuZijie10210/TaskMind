# TaskMind｜AI 对话成果复用

**先推进任务，自然接住成果。**

人们借助 AI对话工具 推进任务时，对话中常会逐渐形成一些值得留下的想法、判断和阶段结果。但它们容易和临时追问、尝试过又放下的方向混在一起；用户忙着完成眼前的事，通常不会停下来整理。等以后想再次使用，可能只记得“之前好像聊过”，却难以找到当时认可的内容，也不确定它能否接上现在的任务。

TaskMind 探索的是：怎样让 AI 对话里产生的有用内容，在之后还能被找到、确认和使用？

## 为什么这些内容没有留下来、用起来？

### 1. 整理要付出成本

用户并非看不到中间产出的价值，只是在做任务时，注意力首先放在下一步怎么推进。此时让他停下来整理、命名、分类和归档，会增加一项额外工作。

他也未必能立刻判断：这段内容以后是否会用到？它是已经形成的阶段结果，还是一次试错、一个尚未确认的想法？为了不确定的未来价值，持续维护一套资料库很难成为自然习惯。

### 2. 保存了也不一定会再用

之后想复用时，用户可能只记得“我好像在上个任务里讨论过”，却想不起具体在哪一轮、当时为什么得出这个判断，也不确定它现在是否适用。如果还要翻聊天记录、猜关键词、重新理解背景，直接再问一次 AI 可能更省事。

困难不仅是找不到，还包括想不起、判断不了、接不上当前问题。

### 3. 留下与再用，都需要信任

用户需要弄清四件事：内容从哪段讨论或哪份资料而来；自己是否真的认可它；它是否贴合当下任务；系统带入新对话的究竟是哪部分历史内容。这里的信任不只是内容是否正确，还关系到来源、个人判断、使用语境和调用边界。

这些问题来自早期以学习任务为切入点的[用户访谈、问卷和竞品分析](https://docs.qq.com/slide/DWnBuUUdwUmhDS01Y)。TaskMind 从课程汇报等任务开始展示，但设计关注的是需要多轮推进的任务，不限于学生场景。

## TaskMind 怎么回应？

TaskMind 以一件待完成的事为单位组织 AI 对话。在每个任务中：

- **主线：** 这件事的主要推进过程。
- **支线：** 推进中分出来、值得单独追问的问题。它从当时的主线展开，之后独立探索，也可以被放下。
- **成果：** 对话中产生、经用户确认值得保留的阶段产出，比如一个框架、一项判断或一种方法。它不是整段聊天记录。

整个使用过程分为三步：

1. **先推进任务。** 主线负责目标，支线承接临时探索，让不同方向不会全混在同一条长对话里。
2. **需要时再整理。** 用户觉得一段讨论值得留下，或想把支线的收获带回主线时，主动发起整理。AI 提出可能值得保存的内容；用户查看来源、修改标题、摘要或正文，也可以移除候选，再决定是否确认。保存后仍能回看这份成果来自哪些消息。
3. **以后按记得的线索找回。** 知道具体内容时，输入 `@成果` 选择它；只记得内容来自哪个任务时，输入 `@任务`，系统从该任务已确认的成果中匹配相关内容，再带入当前对话。

不同对话不会自动交换全部聊天过程。支线里的讨论不会自行进入主线；选中一个旧任务时，系统也只查找其中已确认的成果，不读取该任务的原始聊天。消息会保留实际引用内容的快照，方便回看当时使用了什么。

**不是保存聊了什么，而是保存聊出了什么。** 整理由用户发起、AI 帮忙提炼；之后从用户记得的任务出发找回成果。用户无需另外维护一套知识库。

## 当前进展与下一步

[在线 Demo](https://taskmind-production-050c.up.railway.app/)已支持主线、支线、成果整理与确认，以及 `@成果`、`@任务` 两种引用。预置任务用于体验这条流程。

下一步将优化何时提示用户整理、AI 提炼内容的范围，以及确认时的展示方式；重点观察用户是否愿意保留这些候选内容，以及它们是否在后续任务中真的被使用。目前这些仍是待验证的设计判断。
