# TaskMind

**先推进任务，自然接住成果。**

TaskMind 面向需要多轮推进的任务。对话过程中形成的判断、框架和方法常埋在聊天记录里，下一次需要时却难以找回。

TaskMind 关注的是**保存聊出了什么，而不是保存聊了什么**：用户围绕任务推进，在需要时主动整理一段对话；AI 提炼候选成果，用户审核并确认。确认后的成果可以通过 `@成果` 或 `@任务` 在后续对话中调用。

- [在线体验](https://taskmind-production-050c.up.railway.app/)
- [产品设计简介](https://taskmind-production-050c.up.railway.app/about)

## 设计边界

一个任务包含主线和从特定主线节点展开的支线。支线继承展开时的主线背景，此后独立探索；主线与支线不会自动同步后来的对话。支线可以继续、放下，或通过用户主动整理形成成果。

**对话之间不共享过程，只共享用户明确调用的已确认成果。**用户未确认的候选或支线聊天不能经由引用进入主线或另一任务。系统保存发送时实际引用的成果快照，使已发消息的依据可追溯。

| 操作 | 适用情况 | 使用范围 |
| --- | --- | --- |
| `@成果` | 知道要用哪一份成果 | 直接引用指定的已确认成果 |
| `@任务` | 记得成果来自哪项任务，不记得具体标题 | 只从该任务已确认成果中匹配相关内容，不读取该任务的原始聊天 |

用户不用刻意维护知识库，仍能在推进任务时留下和复用阶段产出。成果可以是结论、案例、资料、框架、判断、模板或方法；它们由 AI 提议、由用户决定是否保存。

首次访问会加载两个预置任务，供访客直接查看主线、支线、已确认成果与引用。

## 技术结构

React 前端与 Express API 由一个 Node 服务提供；PostgreSQL 保存任务、消息、支线快照、候选整理记录、成果及引用快照。模型调用在服务端通过 OpenAI 兼容 Chat Completions 接口完成；密钥不进入浏览器。

`@任务` 的相关性选择只读取该任务已确认成果的标题、类型和摘要，再将选中的成果内容加入本轮上下文；不会读取历史任务的原始对话。

## 本地运行

需要 Node.js 20+ 和 PostgreSQL。复制 `.env.example` 为 `.env`，设置以下变量：

| 变量 | 用途 |
| --- | --- |
| `DATABASE_URL` | PostgreSQL 连接地址 |
| `AI_API_KEY` | AI 服务提供方的密钥 |
| `AI_BASE_URL` | 与密钥对应的 Chat Completions API 基础地址，通常以 `/v1` 结尾 |
| `AI_MODEL` | 提供方支持的模型，须支持流式输出及 `max_tokens` |
| `SESSION_SECRET` | 生产环境至少 32 个随机字符，部署后保持稳定 |
| `PUBLIC_ORIGIN` | 可选；公开站点的来源地址 |

密钥、地址和模型需要属于同一服务提供方。不要将 `.env` 或密钥提交到公开仓库。

```sh
npm ci
node --env-file=.env app/migrate.cjs
npm run build
node --env-file=.env app/server.js
```

默认访问 `http://localhost:3000`。Docker 部署时启动过程会应用新增数据库迁移。健康检查路径为 `/healthz`；`/api/health/modules` 仅检查模块配置与连接状态，不检验密钥余额。

## 当前范围

公开体验按浏览器隔离访客任务，定期清理不活跃数据，并限制每日对话与整理次数。现有版本没有真实用户效果数据，也没有长对话的严格上下文预算；长任务仍可能碰到模型上下文限制。请勿输入敏感资料。

运行 `npm test` 检查对话上下文、引用边界、访客隔离和示例；运行 `npm run build` 检查前端构建。真实模型回复、候选质量和跨任务选择效果还需在已配置数据库与模型的部署环境中验证。
